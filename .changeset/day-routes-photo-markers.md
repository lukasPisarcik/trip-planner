'trip-planner': minor
---

The trip map now draws every itinerary day at once instead of one dotted day at a time: each day with coordinates gets a road-following driving route from the Maps JS Routes library (the deprecated DirectionsService is never used; requests are chunked to ≤10 intermediates so they stay on the Essentials SKU, and an unroutable or still-loading segment shows a dashed straight line instead) plus a photo tile per stop with its order badge (44px at street zoom, shrinking to 30px and 20px as you zoom out so a city's stops don't pile into a blob; line weights scale the same way), coloured from a new 8-token `--day-N` palette and listed in a glass legend bottom-left. Focus is now two-way with one source of truth in `TripView`: opening a day card, clicking a route, a stop marker or a legend row renders that day in the primary colour, fades every other day and all category pins to 25% and fits the viewport to it — a map- or legend-initiated focus also switches to the Itinerary tab and scrolls the card below the tab bar (once, so switching tabs later never jumps the page) — while closing the card, re-clicking the route, clicking empty map or "Show all days" restores the all-days view. Computed paths are cached in memory and in `localStorage` (keyed by a hash of the segment's coordinates, Zod-validated on read, 120-entry cap) so reloading a trip spends zero route requests, a failed segment is never re-requested within a page load, and a theme flip rebuilds the map with layers, focus and dimming intact. Itinerary activities gain an optional `image`, backfilled from Wikimedia on `create_trip`, `replace_itinerary` and `upsert_itinerary_days` for coord-bearing stops only, skipping generic non-place stops ("Breakfast", "Free afternoon") and applying the title relevance guard so no stop gets a random photo; the co-pilot prompt now asks for `find_image` on real-place stops. Trips saved before this change have no stop photos yet — run `bun run backfill:images` once (optionally `-- --dry-run` or specific slugs) to fill them through the same service-layer backfill. Requires the Routes API to be enabled on the Maps key's Cloud project (see `.env.example`).
